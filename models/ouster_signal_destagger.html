핵심 개념

Ouster의 2D 이미지는 카메라 이미지처럼 모든 row가 같은 column 기준으로 딱 맞춰진 데이터가 아니다. 센서가 회전하면서 여러 beam을 동시에 쏘기 때문에, 각 레이저 row는 실제 방위각 기준으로 조금씩 좌우로 밀려 있다.

그래서 raw Signal 배열을 그대로 2D 이미지로 표시하면 가로줄이 흔들리거나 물결처럼 보인다. 이 상태를 보통 staggered image라고 보고, 표시 전에 destagger 보정을 한다.
Range
RNG19. 거리값. PCD 좌표와 Depth의 기반.
Reflectivity
RFL8. 보정 반사율. 물체 표면 성질을 보기 좋음.
Signal
SIG16. 수신 신호 세기. 2D 흑백 이미지로 보기 좋음.
NearIR
NIR16. 주변 적외선 성분.

JSON에 들어있는 힌트

Ouster metadata의 lidar_data_format.pixel_shift_by_row가 row별 보정값이다. 이 값은 row마다 몇 column을 원형 이동해야 하는지 알려준다.

"pixel_shift_by_row": [12, 4, -4, -12, 12, 4, -4, -12, ...]
row 0+12
row 1+4
row 2-4
row 3-12
우리 샘플은 이 패턴이 반복된다. 즉 4개 row 단위로 서로 다른 column shift가 들어가서 raw 이미지를 그대로 보면 지글거리는 느낌이 강하다.

계산식

먼저 V3 payload는 Ouster column-major 순서로 들어온다. 그래서 row-major 2D 이미지로 한 번 펼친 다음, row별 shift를 적용한다.

1. Ouster payload를 2D 이미지 좌표로 펼치기

W = columns_per_frame = 1024
H = pixels_per_column = 128

sourceIndex = column * H + row
targetIndex = row * W + column

image[targetIndex] = signal[sourceIndex]

2. row별 destagger 적용

shift = pixel_shift_by_row[row]
normalizedShift = ((shift % W) + W) % W

targetColumn = (column + normalizedShift) % W
destaggered[row * W + targetColumn] = image[row * W + column]
원형 이동이 중요하다. 왼쪽이나 오른쪽 끝으로 밀려 나간 값은 버리는 것이 아니라 반대쪽으로 감긴다. 360도 라이다 이미지는 좌우 끝이 이어지는 구조이기 때문이다.

우리 코드에서 한 일

1
bin 로드
V3 header를 읽고 Ouster 파일인지 확인한다.
2
json 찾기
같은 폴더에서 원본 이름의 Ouster metadata JSON을 찾는다.
3
shift 읽기
pixel_shift_by_row를 읽어 summary에 저장한다.
4
Signal 보정
Signal 2D 이미지를 만들 때 row별 circular shift를 적용한다.
// row-major 이미지로 펼친 뒤 row마다 보정
for (var row = 0; row < H; row++)
{
  shift = pixelShiftByRow[row];
  normalizedShift = ((shift % W) + W) % W;

  for (var column = 0; column < W; column++)
  {
    targetColumn = (column + normalizedShift) % W;
    destaggered[row * W + targetColumn] = image[row * W + column];
  }
}

흑백 표시 계산

Signal 값은 16비트라 그대로 화면에 그리면 너무 어둡거나 너무 밝게 뭉칠 수 있다. 그래서 상위 일부 밝은 값에 끌려가지 않도록 98% 지점을 기준으로 자동 레벨링한다.

valid = signal values where value > 0
highClip = percentile(valid, 98%)

normalized = clamp(signal / highClip, 0, 1)
gray = round(normalized * 255)
raw 값

센서에서 나온 실제 Signal 세기. 단위와 범위가 크다.

auto level

화면에서 보기 좋게 0..1로 정규화한다.

gray image

0은 검정, 255는 흰색으로 표시한다.

주의할 점

  • .bin 옆에 원본 .json이 있어야 row shift 보정이 가능하다.
  • 파일명이 _ouster_v3_reflectivity 같은 suffix를 가져도 원본 이름의 JSON을 찾아보도록 처리했다.
  • destagger는 2D Signal 보기용이다. 3D PCD 좌표는 이미 좌표 계산이 끝난 값이라 같은 방식으로 밀면 안 된다.
  • Studio와 완전히 같은 톤을 내려면 감마, 대비, 노이즈 억제 같은 후처리를 추가로 맞춰야 한다.
