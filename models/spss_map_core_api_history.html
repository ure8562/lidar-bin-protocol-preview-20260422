SPSS Map Core DLL API 변경 이력과 현재 구조

이 문서는 01. port/LabViewLidar/SpssMapCore DLL을 현재 engine handle 기반으로 정리한 결과를 설명합니다. 특히 SMC_ProcessFrame은 처리만 수행하고, 결과는 SMC_GetLast... API로 가져오는 v11 구조를 기준으로 합니다.

Current API v11 Generated: 2026-05-14 Process → GetLast UTF-8

1 현재 결론

API 방향

현재 DLL은 handle 없는 단발성 API를 제거하고, SMC_Create로 만든 engine handle을 중심으로 동작합니다. 호출자는 설정을 engine에 저장하고, frame을 처리한 뒤 마지막 결과를 필요한 만큼 가져갑니다. 

SMC_Create(&handle)
SMC_SetConfig(handle, &config)
SMC_ProcessFrame(handle, points, pointCount)

SMC_GetLastBevMapInfo(handle, &mapInfo)
SMC_GetLastAnalysisInfo(handle, &analysisInfo)
SMC_GetLastBevCells(handle, cells, capacity, &writtenCount)
SMC_GetLastCandidateRegions(handle, regions, capacity, &writtenCount)

SMC_Destroy(handle)

왜 이렇게 바꿨나

이전에는 SMC_ProcessFrame이 처리와 결과 복사를 동시에 맡아서 인자가 많아졌습니다. v11부터는 처리와 결과 조회를 분리해서 함수 의미가 단순해졌고, LabVIEW/C#/다른 호출자도 같은 순서로 사용할 수 있습니다.

  • ProcessFrame: frame 처리와 내부 last result 갱신
  • GetLast...: 마지막 결과를 호출자 버퍼로 복사
  • 새 frame을 처리하면 이전 결과는 덮어씀
  • SetConfig가 호출되면 이전 결과는 무효 처리

2 API 버전별 변경 이력

v1~v2는 초기 실험 단계라 세부 ABI 기록이 제한적입니다. 아래 표는 현재 코드와 작업 흐름을 기준으로 복원한 실무용 변경 이력입니다.

버전 핵심 변경 의미 현재 상태
v1 초기 BEV grid 생성 실험 원본 점을 ROI/grid 기준으로 cell에 누적하는 최소 형태입니다. 폐기됨
v2 기본 BEV config와 단발성 호출 정리 SMC_BuildBevMap 중심의 handle 없는 함수 구조였습니다. 폐기됨
v3 SpssBevCell 정보 확장 cell별 maxHeight, minHeight, heightSum, reflectivitySum, pointCount를 담기 시작했습니다. 구조체 유지
v4 가변 설정형 BEV 흐름 실험 고정 기본값 대신 UI에서 grid/ROI를 바꿔가며 테스트하는 방향으로 이동했습니다. SpssConfig로 통합
v5 설정 구조 분리 SpssBevConfig, 후보 설정, 정렬 설정, noise 설정을 나누는 방향으로 정리했습니다. 유지
v6 engine handle 구조 도입 SMC_Create, SMC_Destroy, SMC_SetConfig, SMC_ProcessFrame 형태가 생겼습니다. 기반 유지
v7 좌표 정렬을 DLL로 이동 UI가 변환한 BEV 좌표를 넘기는 대신, 원본 meter 좌표를 넘기고 DLL에서 rotation/projection/flip을 적용하게 했습니다. 유지
v8 noise filter를 DLL로 이동 reflectivity 기반 점 필터와 cell point count 필터를 DLL 내부 처리로 옮겼습니다. 유지
v9 후보 사각형 검출을 DLL로 이동 SMC_ProcessFrameWithCandidates로 BEV cell과 후보 영역을 함께 반환했습니다. v11에서 제거
v10 handle 없는 공개 API 제거 SMC_SetDefaultBevConfig, SMC_BuildBevMap, SMC_BuildBevMapWithConfig를 제거하고 engine 중심 API만 남겼습니다. 유지
v11 Process → GetLast 구조로 변경 SMC_ProcessFrame은 처리만 하고, 결과는 SMC_GetLast... 함수로 가져오게 했습니다. SMC_ProcessFrameWithCandidates는 제거했습니다. 현재 버전

3 현재 공개 API

API 역할 주의
SMC_GetApiVersion 현재 C ABI 버전을 반환합니다. 현재 값은 11입니다. UI는 11 미만이면 로딩하지 않습니다.
SMC_GetDefaultConfig 새 engine/UI 설정 패널에 사용할 기본 SpssConfig를 채웁니다. engine 상태는 바꾸지 않습니다.
SMC_Create SPSS 분석 engine을 만들고 handle을 반환합니다. 반환 handle은 이후 모든 API의 기준입니다.
SMC_Destroy engine을 해제합니다. 해제 후 handle 재사용 금지.
SMC_GetConfig 현재 engine 설정을 복사해 가져옵니다. 일부 설정만 바꾸고 싶을 때 기준값으로 사용합니다.
SMC_SetConfig 수정한 전체 설정을 engine에 반영합니다. 설정이 바뀌면 이전 last result는 비웁니다.
SMC_ProcessFrame 원본 점 배열을 현재 설정으로 처리하고 engine 내부 last result를 갱신합니다. 결과를 직접 반환하지 않습니다.
SMC_GetLastBevMapInfo 마지막 BEV map의 폭/높이/cell 개수를 가져옵니다. cell 배열 할당 전 먼저 호출합니다.
SMC_GetLastAnalysisInfo 입력점/변환점/ROI점/occupied cell/후보 개수 요약을 가져옵니다. UI Overview와 batch export에 사용하기 좋습니다.
SMC_GetLastBevCells 마지막 BEV cell 배열을 호출자 버퍼로 복사합니다. outputCells=null이면 필요한 개수만 확인할 수 있습니다.
SMC_GetLastCandidateRegions 마지막 후보 사각형 배열을 호출자 버퍼로 복사합니다. 후보 좌표는 BEV fine grid 기준입니다.

4 현재 DLL 내부 구성

Engine 상태

SpssEngine은 설정과 마지막 frame 결과를 보관합니다.

magic
config
lastMapInfo
lastAnalysisInfo
lastCells
lastCandidates

설정 묶음

SpssConfig 하나 안에 BEV, 후보, 정렬, 필터 설정이 들어갑니다.

SpssConfig
  bev
  candidate
  alignment
  noise

마지막 결과

처리 결과는 Get API가 복사해 갈 때까지 engine 내부에 남습니다.

lastMapInfo
lastAnalysisInfo
lastCells[]
lastCandidates[]
1. 입력 원본 LiDAR 점을 meter 단위 SpssPoint로 전달
2. 정렬 rotation X/Y/Z, projection plane, flip 적용
3. BEV ROI/grid 기준으로 SpssBevCell 누적
4. 필터 reflectivity와 cell point count 기준 noise 제거
5. 후보 local density + depth threshold로 후보 사각형 검출

5 핵심 구조체

SpssPoint

호출자가 DLL에 넘기는 원본 점입니다. 좌표는 meter 단위입니다.

float x;
float y;
float z;
float reflectivity;

SpssBevCell

BEV grid 한 칸의 누적 정보입니다.

float maxHeight;
float minHeight;
float heightSum;
float reflectivitySum;
uint32_t pointCount;

SpssCandidateRegion

후보 사각형 정보입니다. 좌표는 BEV fine grid 기준입니다.

id, x, y, width, height
occupiedCellCount
gridSizeMeters
minDepth, maxDepth
averageDepth
averageReflectivity
confidence

SpssAnalysisInfo

Overview와 batch 결과에 쓰기 좋은 frame 요약입니다.

inputPointCount
transformedPointCount
roiPointCount
bevWidth, bevHeight
requiredCellCount
occupiedCellCount
requiredCandidateCount

6 호출 예시

SpssHandle handle = 0;
SMC_Create(&handle);

SpssConfig config{};
SMC_GetDefaultConfig(&config);

// UI 또는 LabVIEW에서 config.bev / config.alignment / config.noise / config.candidate 수정
SMC_SetConfig(handle, &config);

// frame 처리: 결과는 DLL 내부 last result에 저장됨
SMC_ProcessFrame(handle, points, pointCount);

SpssBevMapInfo mapInfo{};
SMC_GetLastBevMapInfo(handle, &mapInfo);

SpssAnalysisInfo analysis{};
SMC_GetLastAnalysisInfo(handle, &analysis);

std::vector<SpssBevCell> cells(mapInfo.requiredCellCount);
std::int32_t writtenCellCount = 0;
SMC_GetLastBevCells(
    handle,
    cells.data(),
    static_cast<std::int32_t>(cells.size()),
    &writtenCellCount);

std::int32_t candidateCount = 0;
SMC_GetLastCandidateRegions(handle, nullptr, 0, &candidateCount);

std::vector<SpssCandidateRegion> candidates(candidateCount);
SMC_GetLastCandidateRegions(
    handle,
    candidates.data(),
    candidateCount,
    &candidateCount);

SMC_Destroy(handle);

8 제거된 API와 이유

제거된 API 제거 이유
SMC_SetDefaultBevConfig handle 없이 BEV 기본값만 다루는 단발성 API라 engine 중심 구조와 맞지 않습니다. 현재는 SMC_GetDefaultConfig가 전체 기본 설정을 제공합니다.
SMC_BuildBevMap 고정 기본값으로 BEV만 생성하던 초기 API입니다. 현재는 SMC_ProcessFrame이 전체 전처리/BEV/후보 검출을 수행합니다.
SMC_BuildBevMapWithConfig 호출마다 config를 직접 넘기는 구조였습니다. 현재는 SMC_SetConfig로 engine에 설정을 저장한 뒤 frame을 처리합니다.
SMC_ProcessFrameWithCandidates 처리와 결과 복사를 동시에 하면서 인자가 길어졌습니다. v11부터는 SMC_ProcessFrame 처리 후 SMC_GetLast...로 가져옵니다.
