SPSS Map Core DLL 동작 흐름 도식

01. port/LabViewLidar/SpssMapCore DLL의 내부 동작을 단계별 다이어그램으로 정리한 문서입니다. LiDAR 점 데이터가 어떻게 BEV 지도와 후보 박스로 변환되는지, handle 기반 lifecycle은 어떻게 흘러가는지 시각적으로 추적할 수 있습니다.

API v11 SpssMapCore.cpp 1653 lines Process → GetLast 2026-05-14

1 시스템 개요

SpssMapCore는 LiDAR 점군(PCD) 한 프레임을 받아 BEV(Bird's-Eye-View) 격자 지도와 후보 박스 영역을 생성하는 Windows DLL입니다. C ABI로 노출되어 LabVIEW와 C# UI(P/Invoke)에서 동일하게 호출할 수 있습니다.

호출자 ↔ DLL 구조 — Engine은 handle 뒤에 숨고, 결과는 모두 내부에 보관

입력

원본 LiDAR 점 배열 SpssPoint[] (x, y, z meter + reflectivity)

출력

BEV cell 격자 + 후보 사각형 박스 + 프레임 요약 (모두 engine 내부 last result)

2 전체 동작 흐름 (Lifecycle)

handle 생성부터 해제까지 표준 호출 순서입니다. SetConfig는 호출 직후 이전 결과를 무효화하고, ProcessFrame은 결과를 내부에만 저장합니다 — 호출자는 GetLast*로 필요한 만큼만 꺼냅니다.

표준 lifecycle — 점선은 반복 호출 경로
핵심 원칙: ProcessFrame은 결과를 반환하지 않습니다. 모든 결과는 engine 내부 last result 버퍼에 저장되고, 호출자는 필요한 결과만 GetLast*로 가져갑니다. 이 분리 덕분에 함수 시그니처가 단순해지고 호출자가 한 번에 받을 결과의 종류·크기를 선택할 수 있습니다.

3 ProcessFrame 5단계 파이프라인

입력 점 배열이 BEV 격자와 후보 박스로 변환되는 내부 처리 과정입니다.

파란 단계는 순차 처리, 좌/우 분기는 결과 저장 위치
1

점 단위 noise filter

enableNoiseFilter == 1이면 reflectivity < minReflectivity인 점을 버립니다. 필터가 꺼져 있으면 호환성을 위해 reflectivity 값과 무관하게 통과시킵니다. NaN/Inf reflectivity는 필터 ON 상태에서만 버립니다.

2

좌표 변환

alignment 설정에 따라 Roll(X) → Pitch(Y) → Yaw(Z) 순서로 회전한 뒤, projection plane(TOP_XY / FRONT_YZ / SIDE_XZ)을 선택해 축을 재배치하고, 마지막에 flipX/flipY를 적용합니다. UI(C#)에서 검증한 회전 순서와 동일하게 유지됩니다.

3

BEV 격자 누적

ROI [minX, maxX) × [minY, maxY) × [minZ, maxZ) 안의 점만 cellX = (x - minX) / grid로 인덱스를 계산해 해당 셀에 추가합니다. 각 셀은 maxHeight, minHeight, heightSum, reflectivitySum, pointCount를 누적합니다. float 반올림으로 마지막 셀 밖 인덱스가 나오면 방어적으로 버립니다.

4

셀 단위 noise filter

pointCount < minCellPointCount인 셀을 통째로 초기화합니다. 점은 많지만 격자 한 칸에 모이지 못한 산발성 노이즈를 제거하는 효과가 있습니다. 필터가 꺼져 있거나 임계값이 1 이하면 건너뜁니다.

5

후보 박스 검출

fine BEV를 coarse grid로 다운샘플 → local density mask로 작은 틈 메우기 → BFS 4-방향 연결(깊이 차이로 끊기) → minRegionCells 이상만 채택 → 크기 순 정렬 후 maxCandidateCount만 보존. 자세한 흐름은 섹션 6에 있습니다.

4 좌표 변환 상세

원본 LiDAR meter 좌표를 BEV 누적용 좌표로 바꾸는 3단계입니다. 단계 순서를 바꾸면 UI 검증 결과와 달라지므로 X → Y → Z 회전, 그 다음 투영, 마지막 flip 순으로 고정되어 있습니다.

변환 순서: 회전 (X→Y→Z) → 투영면 선택 → flip — 이 순서가 UI 검증 결과와 일치
왜 double로 계산? 회전 함수 안에서 cos/sin은 모두 double로 계산한 뒤 float으로 캐스팅합니다. UI(C# Math.PI) 검증 결과와 같은 값을 내기 위한 의도적 설계입니다.

5 BEV 격자 누적 방식

BEV 격자는 gridSizeMeters 크기의 정사각 셀로 ROI를 덮습니다. 각 점은 자신이 속한 셀에 통계값으로 누적됩니다.

한 셀(파란 박스)에 들어온 점들이 통계값으로 누적되는 모습

ROI 경계 처리

상한은 반열림 구간 [min, max)로 처리합니다. x >= maxX인 점은 버려지고, 경계 위 점이 두 셀에 중복 배정되지 않습니다.

float 반올림 방어

(x - minX) / grid 계산 후에도 cellX >= width가 될 수 있어, 인덱스 범위 체크를 한 번 더 거칩니다. 안전한 메모리 접근을 위한 마지막 방어선입니다.

6 후보 박스 검출 알고리즘

가장 복잡한 단계입니다. fine BEV cell에서 시작해 5개의 sub-step을 거쳐 후보 사각형 리스트를 만듭니다.

A → B → C → D → E 5-step 흐름과 단계별 시각 변환

주요 파라미터

파라미터 역할 의미
candidateGridSizeMeters step A coarse 격자 한 칸 크기. bev grid보다 클수록 다운샘플 비율 ↑
localRadiusCells step B 주변을 볼 반경. 0이면 mask 비활성화
minLocalCells step B 반경 안에 필요한 최소 occupied cell 수
depthThresholdMeters step C 이웃 셀 간 평균 depth 차이 한계. 클수록 연결 관대
minRegionCells step D 후보로 인정할 최소 영역 크기. 작은 노이즈 군집 제거
maxCandidateCount step E 최종 후보 개수 상한. 큰 영역 우선으로 잘림
confidence 계산: regionCellCount / boxArea — bounding box를 얼마나 빽빽이 채웠는지를 나타냅니다. 1.0에 가까울수록 직사각형에 가까운 영역, 0.5 미만이면 비스듬하거나 흩어진 영역입니다.

7 데이터 구조 관계도

engine은 SpssConfig 하나와 4종의 마지막 결과를 보관합니다. 설정은 4개 sub-config로, 결과는 입력 점 → BEV cell → 후보 박스로 흐릅니다.

SpssEngine 내부 — 설정(파랑) + 마지막 결과(주황) → GetLast API로 호출자에게 전달

8 호출 시퀀스 다이어그램

호출자와 DLL 사이의 시간 순 메시지 교환입니다. GetLast*는 두 번 호출 패턴(size query → 복사)을 사용합니다.

파란 화살표 = 호출, 초록 점선 = 응답 — GetLast*는 size query → 복사 두 번 호출
SpssHandle h = 0;
SMC_Create(&h);

SpssConfig cfg{};
SMC_GetDefaultConfig(&cfg);
// cfg 수정...
SMC_SetConfig(h, &cfg);

SMC_ProcessFrame(h, points, n);

SpssBevMapInfo info{};
SMC_GetLastBevMapInfo(h, &info);

std::int32_t needed = 0;
SMC_GetLastBevCells(h, nullptr, 0, &needed);

std::vector<SpssBevCell> cells(needed);
std::int32_t written = 0;
SMC_GetLastBevCells(h, cells.data(), needed, &written);

SMC_Destroy(h);

9 상태 코드와 안전성

모든 공개 API는 std::int32_t 상태 코드를 반환합니다. 호출자는 == SMC_STATUS_OK로 판단하고, 그 외는 모두 오류로 처리합니다.

값 코드 의미
0 SMC_STATUS_OK 성공
-1 SMC_STATUS_INVALID_ARG null 포인터, 음수 개수 등 잘못된 인자
-2 SMC_STATUS_OUTPUT_TOO_SMALL 호출자 버퍼가 필요한 개수보다 작음 (size query로 재시도)
-3 SMC_STATUS_INVALID_HANDLE handle이 null이거나 magic 검증 실패 (해제된 handle 포함)
-4 SMC_STATUS_OUT_OF_MEMORY bad_alloc을 C ABI 안전한 코드로 변환
-5 SMC_STATUS_CONFIG_OUT_OF_RANGE NaN/Inf, 음수 grid, 잘못된 enum 등 계산 불가능한 설정
-100 SMC_STATUS_NOT_IMPLEMENTED 예약된 미구현 경로

안전성 메커니즘

handle 검증

모든 handle은 내부에서 magic = "SPSS" 표식으로 검증합니다. Destroy 시점에 magic을 0으로 덮어 use-after-free를 빠르게 잡아냅니다.

NaN/Inf 차단

모든 설정값에 std::isfinite를 적용해 인덱스 계산이 깨지는 경로를 차단합니다. ROI 안 점 좌표에도 동일하게 적용됩니다.

오버플로 방지

BEV 크기는 int64로 곱한 뒤 int32 범위 검사를 거칩니다. 설정이 너무 크면 CONFIG_OUT_OF_RANGE로 미리 거부합니다.

예외 차단

ProcessFrame은 bad_alloc을 잡아 OUT_OF_MEMORY로 변환합니다. C ABI 경계 밖으로 C++ 예외가 새지 않습니다.

경계 처리

ROI는 반열림 [min, max)로 중복 배정을 막고, float 반올림으로 발생할 수 있는 out-of-range 인덱스는 한 번 더 클램프합니다.

스레드 안전성

engine 내부에 락이 없습니다. 같은 handle을 여러 스레드가 동시에 호출하면 race가 발생합니다. 호출자가 외부 락으로 직렬화하거나, 멀티 핸들을 사용해야 합니다.

UI 호환성: SMC_GetApiVersion은 현재 11을 반환합니다. LidarInspector UI는 v11 미만 DLL을 로딩하지 않으므로, ABI 변경이 있을 때마다 이 값을 올려야 합니다.
